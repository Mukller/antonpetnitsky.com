Safalife.

A courier delivery app designed, built and deployed to production for a logistics company in Uzbekistan. Flutter mobile, FastAPI backend, OSRM routing, 24/7 self-hosted.

Status
In production

Since 2025. Backend, database, and routing all on my own infrastructure with watchdog self-healing and nightly backups. Same setup as the homelab page.

Couriers

~30 active couriers in Tashkent, growing monthly.

What I built
Mobile app

Flutter. One screen per action. Order flow, navigation, delivery status. Built for couriers who don't have time for training.

Backend

FastAPI + PostgreSQL. Order lifecycle, courier accounts, health endpoints, bot-driven monitoring. Async throughout.

Routing

Self-hosted OSRM. Real road routing without per-request API fees. Whole Uzbekistan in one tile set.

Bot

aiogram 3, RU + UZ. Client bot for placing orders, courier bot for accepting them, admin bot for monitoring.

Release pipeline

Signed APK + AAB builds shipped automatically on git tag. Updates go out without manual assembly.

Stack
Mobile

Flutter, Riverpod, GoRouter, Geolocator, Dio, Firebase Messaging, local notifications.

Backend

FastAPI, SQLAlchemy 2.0 async, alembic, PostgreSQL 16, Redis for ephemeral state, OSRM for routing.

Bot

aiogram 3, asyncpg, watchdog, OpenRouter for LLM features (auto-summarise delivery notes).

Infra

Docker compose on the home server, Cloudflare Tunnel (no public IPs in app config), nightly pg_dump backups.

Lessons from production
OSRM tile prep

Building the tile set for the whole country takes 6 hours and 32 GB of RAM. Do it once on a beefy machine, ship the prebuilt set, never rebuild in production.

Couriers use the app differently

They hold the phone with one hand, in the sun, while walking. Big buttons. High contrast. The dark theme tests better than the light theme in real usage.

Firebase broke once

Push notifications stopped for 4 hours on a Sunday. Nobody noticed — couriers were in voice calls. I now consider Firebase push as a nice-to-have, not a critical path.
